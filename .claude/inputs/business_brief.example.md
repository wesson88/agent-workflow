# 业务简报（Business Brief）- 示例模板

> 复制此文件为 `business_brief.md` 后填写。
> `business_brief.md` 是 `product_manager` 的主要输入，优先级高于 `TASK` 环境变量。
> 没有必要把所有章节都写满——写清楚你真正知道的部分即可，未知项留给 PRD 的"待确认项"。

---

## 1. 一句话项目描述
<例：给独立开发者用的简洁任务看板，支持多人协作，核心差异是跟 GitHub Issues 双向同步。>

## 2. 目标用户
<具体到角色，例：1-5 人的独立开发团队、技术创业公司早期 CTO；不要写"所有人"。>

## 3. 要解决的核心问题
<用户当前是怎么做的？痛点是什么？为什么现有方案不够好？>

## 4. 期望的核心能力（3~7 条）
- <例：任务的创建、拖拽排期、状态流转>
- <例：与 GitHub Issues 的双向同步>
- <例：按成员/标签/里程碑过滤>

## 5. 明确不做的事
<避免范围蔓延，例：不做甘特图、不做时间统计、不做移动端 App。>

## 6. 约束与边界
- 预算 / 时间窗口：<例：2 个月 MVP>
- 技术栈偏好：<若有，否则留空让架构师选>
- 合规 / 安全 / 性能的硬约束：<例：用户数据须加密存储、支持千人并发>

## 7. 成功标准
<怎样算成功？例：3 个月内 50 个付费团队、GitHub 同步延迟 < 5s。>

## 8. 其他背景
<竞品链接、用户访谈摘要、老板的原话，任何有助于理解需求的上下文。>
