# 跨项目部署指南

## 核心思路

工作流的所有逻辑都在 `.claude/` 目录中，只需将它复制到目标项目即可。项目特定内容只有两个文件：

| 文件 | 说明 |
|------|------|
| `requirements/PRD.md` | 新项目的产品需求 |
| `docs/tech_stack.md` | 新项目的技术栈规范 |

---

## 部署步骤

### 1. 复制 `.claude/` 目录到目标项目根目录

```bash
cp -r /path/to/workflow/.claude/ /your/new/project/.claude/
```

### 2. 重写 PRD

替换 `.claude/requirements/PRD.md` 为新项目的需求文档。

### 3. 更新技术栈（可选）

修改 `.claude/docs/tech_stack.md`，指定新项目使用的框架与语言，例如 React、FastAPI、Go 等。

### 4. 重置状态

将 `status.json` 中所有技能的状态恢复为初始值，避免旧状态干扰新项目的运行：

- 每个技能的 `status` 改为 `"idle"`
- 每个技能的 `consecutive_failures` 改为 `0`

### 5. 运行工作流

```bash
cd /your/new/project

# 设置 API Key
export ANTHROPIC_API_KEY="your-api-key"

# 方式一：运行完整链路（推荐）
python .claude/script/optimize_all.py

# 方式二：单独运行某个技能（测试用）
TARGET_SKILL=chief_architect TASK="架构分解任务管理系统" \
  python .claude/script/workflow.py

# 方式三：直接调用技能（调试用）
python .claude/skills/chief_architect/main.py --task "架构分解任务管理系统"
```

## 无需修改的文件

以下文件与具体项目无关，直接复用即可：

| 文件/目录 | 说明 |
|-----------|------|
| `skills/*/main.py` | 通用执行器，无项目耦合 |
| `skills/*/skill.md` | 角色定义，通用 |
| `script/workflow.py` | 单技能调度器，通用 |
| `script/optimize_all.py` | 全链路批量执行器，通用 |
| `skills/common.py` | 共享工具库，通用 |

---

## 针对差异较大的项目架构

如果目标项目在技术栈或架构风格上与原项目差异较大，建议额外调整以下内容：

### 修改架构分解规则

编辑 `.claude/docs/rules/arch_decomposition_rules.md`，针对目标项目的架构风格（如微服务、单体、Serverless）调整分解方法论，`chief_architect` 会据此生成不同的 `system_design.md`。

### 扩展或替换技能

如需新增技能（如 `dev_devops`、`dev_test` 等），参考 [README.md](../README.md#扩展技能) 中的扩展步骤：

1. 在 `skills/` 下新建目录，创建 `skill.md` 和 `main.py`
2. 在 `status.json` 的 `skill_registry` 中注册新技能
3. 将新技能加入 `optimize_all.py` 的 `skills_chain`

## 常见问题

**Q: 复制后运行报错找不到模块？**
确认已安装依赖：`pip install anthropic`，且 Python 版本 ≥ 3.9。

**Q: 新项目的技术栈和原项目完全不同，skill.md 还适用吗？**
适用。`skill.md` 定义的是角色职责与输出规范，技术选型由 `tech_stack.md` 控制，两者解耦。

**Q: 想同时维护多个项目的工作流，如何隔离？**
每个项目各自维护独立的 `.claude/` 目录即可，`status.json` 和 `audit.jsonl` 都是项目级文件，互不干扰。
